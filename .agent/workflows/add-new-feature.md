# Workflow: Adding a New Feature

This workflow outlines the step-by-step protocol for designing, implementing, testing, and documenting a new feature in `node-pptx-templater`.

---

## Phase 1: API Design & Contract Specification

1. **Review Rules & Constraints**:
   - Ensure the proposal adheres to zero-dependency execution, pure JS runtime, and OPC/OpenXML standards ([`rules/general.md`](file:///e:/Code/pptx-templater/.agent/rules/general.md)).
2. **Define Fluent API Interface**:
   - Determine whether the feature is accessed via the root orchestrator (`PPTXTemplater`), slide instance (`Slide`), or specialized element manager (`TableManager`, `ChartManager`, etc.).
   - Follow fluent chaining patterns where appropriate (returning `this`).
3. **Draft TypeScript Typings**:
   - Update `types/` or `index.d.ts` with complete type signatures and JSDoc annotations before writing implementation code.

---

## Phase 2: Implementation

1. **Implement Core Logic in Sub-Manager**:
   - Create or extend the manager under `src/managers/` or `src/elements/`.
   - Interact with package contents exclusively through the in-memory VFS (`VirtualFileSystem`).
   - Use `ensureArray()` to handle single vs. array XML nodes safely.
2. **Preserve OpenXML Invariants**:
   - Round all coordinates and measurements to integer EMUs using `Math.round()`.
   - Preserve XML namespaces (`p:`, `a:`, `r:`, `c:`).
   - If adding media or external parts, generate unique `rId` keys and register them in both `.rels` and `[Content_Types].xml`.
3. **Wire to Main Orchestrator**:
   - Expose the method on `src/PPTXTemplater.js` and export necessary helpers from `src/index.js`.

---

## Phase 3: Automated Testing & Verification

1. **Unit Tests (Vitest)**:
   - Create a test file in `tests/` (e.g. `tests/featureName.test.js`).
   - Test:
     - Normal positive path execution.
     - Edge cases (empty data, missing elements, multi-line values).
     - XML AST correctness and attribute presence.
     - Error handling on invalid input.
2. **Run Package Validation**:
   - Verify that presentation files generated by the feature pass OPC schema checks:
     ```bash
     npm test
     npm run validate
     ```
3. **Lint & Code Style**:
   - Run linter and formatting checks:
     ```bash
     npm run lint
     npm run format:check
     ```

---

## Phase 4: Showcase & Documentation

1. **Add Showcase Demonstration**:
   - Add an executable demonstration in `showcase/examples.js`.
   - Ensure `npm run validate` runs the showcase without throwing errors.
2. **Update Documentation**:
   - Add the new method and examples to `README.md` and `project/API_REFERENCE.md`.
